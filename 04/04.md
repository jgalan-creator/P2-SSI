## Ejercicio 4

Utilizando OpenSSL, generad una clave RSA de 2048 bits.

### Apartado 4.a

Indicad el comando utilizado.

#### Respuesta 4.a

<!-- INICIO RESPUESTA -->

Se ha usado OpenSSL 3.5.7. Para generar la clave privada (que contiene el par completo):

```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out privada.pem
```

- `genpkey -algorithm RSA`: genera una clave del algoritmo RSA.
- `-pkeyopt rsa_keygen_bits:2048`: tamaño del módulo `n` de 2048 bits (el exponente público por defecto es 65537).
- `-out privada.pem`: guarda la clave en formato PEM. Se puede proteger con contraseña añadiendo `-aes256`.

El comando clásico `openssl genrsa -out privada.pem 2048` hace lo mismo (en OpenSSL 3 está obsoleto en favor de `genpkey`).

Para extraer la clave pública, que es la que se distribuye:

```bash
openssl pkey -in privada.pem -pubout -out publica.pem
```

### Apartado 4.b

¿Qué números conforman la clave pública?

#### Respuesta 4.b

<!-- INICIO RESPUESTA -->

La clave pública RSA está formada por dos números, **(n, e)**:

- **Módulo `n`**: el producto de los dos primos secretos, `n = p · q`. Es el número de 2048 bits.
- **Exponente público `e`**: el número con el que se cifra (`c = m^e mod n`). OpenSSL usa por defecto `e = 65537 = 0x10001` (= 2^16 + 1), que es primo, y cuya representación binaria tiene solo dos unos, lo que hace el cifrado rápido.

Se pueden ver con:

```bash
openssl pkey -pubin -in publica.pem -text -noout
```

### Apartado 4.c

Probad a cifrar el archivo `secreto.txt` usando la clave pública generada. ¿Encontráis algún problema? Caso afirmativo, plantead una solución al mismo.

#### Respuesta 4.c

<!-- INICIO RESPUESTA -->

**Cifrado directo con RSA:**

```bash
openssl pkeyutl -encrypt -pubin -inkey publica.pem -in secreto.txt -out secreto.rsa
```

```
Public Key operation error
...:rsa routines:ossl_rsa_padding_add_PKCS1_type_2_ex:data too large for key size:...
```

**Problema:** RSA no cifra archivos de cualquier tamaño. Cifra **un único bloque**: el mensaje se convierte en un número `m` que tiene que ser menor que `n`, así que como mucho ocupa lo mismo que el módulo (256 bytes). Además, el relleno (*padding*) obligatorio ocupa parte de ese bloque:

| Relleno | Máximo de datos con clave de 2048 bits |
|---|---|
| PKCS#1 v1.5 (por defecto) | 256 − 11 = **245 bytes** |
| OAEP con SHA-1 | 256 − 2·20 − 2 = **214 bytes** |

Se ha comprobado: con 245 bytes funciona y con 246 falla (con OAEP, 214 funciona y 215 falla). `secreto.txt` es un texto de **1 MiB (1.048.576 bytes)**, unas 4.280 veces el límite, por eso no se puede cifrar.

Aunque se troceara el archivo en bloques de 245 bytes y se cifrara cada uno (como un modo ECB, harían falta unas 4.280 operaciones RSA), no sería buena idea: RSA es del orden de miles de veces más lento que un cifrado simétrico, el resultado ocupa más que el original y no protege el orden ni la integridad de los bloques.

**Solución: cifrado híbrido.** Es lo que hacen en la práctica PGP/GPG, S/MIME o TLS:

1. Se genera una clave simétrica aleatoria (clave de sesión).
2. El archivo se cifra con un algoritmo simétrico (AES-256), que no tiene límite de tamaño y es rápido.
3. Solo la clave de sesión, que es pequeña, se cifra con la clave pública RSA del destinatario.
4. Se envían el archivo cifrado y la clave cifrada.

```bash
# 1. Clave de sesión aleatoria (256 bits en hexadecimal)
openssl rand -hex 32 > clave.txt

# 2. Cifrar el archivo con AES-256
openssl enc -aes-256-cbc -pbkdf2 -salt -in secreto.txt -out secreto.txt.enc -pass file:clave.txt

# 3. Cifrar la clave de sesión con la clave pública RSA (relleno OAEP)
openssl pkeyutl -encrypt -pubin -inkey publica.pem -pkeyopt rsa_padding_mode:oaep -in clave.txt -out clave.txt.enc
```

El destinatario lo descifra con su clave privada:

```bash
# Recuperar la clave de sesión con la clave privada
openssl pkeyutl -decrypt -inkey privada.pem -pkeyopt rsa_padding_mode:oaep -in clave.txt.enc -out clave.dec

# Descifrar el archivo con AES
openssl enc -d -aes-256-cbc -pbkdf2 -in secreto.txt.enc -out secreto.dec -pass file:clave.dec
```

Se ha comprobado con `cmp secreto.txt secreto.dec` que el archivo descifrado es idéntico al original. `secreto.txt.enc` ocupa 1.048.608 bytes (el original más 16 bytes de la cabecera `Salted__` y la sal, y 16 de relleno de AES) y `clave.txt.enc` ocupa 256 bytes (un bloque RSA). Después se debe borrar la clave de sesión en claro (`clave.txt`).

Así se combina lo mejor de cada sistema: la velocidad y la ausencia de límite de tamaño del cifrado simétrico, y la distribución de claves sin secreto compartido previo del asimétrico. Otra opción es usar directamente un formato que ya hace el cifrado híbrido, como `openssl cms -encrypt` / `openssl smime` con un certificado, o GPG.
